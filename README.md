#### 🎯 프로젝트 개요
PC와 FPGA 간의 **UART 양방향 통신 프로토콜**을 설계하고, **FIFO 구조의 데이터 버퍼**를 구현하여 안정적인 데이터 송수신 환경을 구축했습니다. 이를 바탕으로 Basys3 보드의 버튼·스위치 및 PC 키 입력을 통해 동작하는 **디지털 스톱워치와 시계**를 구현하고, **초음파 센서 및 온습도 센서** 데이터를 실시간으로 처리하는 통합 시스템을 설계했습니다.

#### 🗂 시스템 구성 (System Architecture)
전체 시스템은 `top_stopwatch_watch` 모듈을 최상위로 하여 제어부, 시간 측정부, 센서 처리부, 표시부로 구성됩니다.

1.  **Control Unit**: UART 수신 데이터(ASCII)를 디코딩하거나 버튼 입력을 디바운싱하여 각 모듈의 동작 신호를 생성합니다.
2.  **Time Keeper**: 스톱워치와 시계의 상태(FSM)와 데이터패스를 관리합니다.
3.  **Sensor Interface**: 외부 센서와의 직렬 통신을 통해 거리 및 온습도 데이터를 추출합니다.
4.  **Output Mux**: 스위치 설정에 따라 FND에 표시할 데이터를 선택하고, UART Sender를 통해 현재 값을 PC로 전송합니다.

#### 🎛 입출력 소자 및 인터페이스
##### Switches & Buttons
| 소자 | 역할 | 상세 동작 |
| ------ | ------ | ------ |
| **sw** | 카운트 방향 | 0: Up count / 1: Down count |
| **sw** | 메인 모드 선택 | 0: Watch / 1: Stopwatch |
| **sw** | 시간 표시 단위 | 0: sec.msec / 1: hour.min |
| **sw** | 센서/시계 모드 선택 | 0: SR04-Watch / 1: DHT11-Stopwatch |
| **btn_l / btn_r** | 기능 제어 | 스톱워치 Clear/Run-Stop, 시계 수정 위치 선택 |
| **btn_u / btn_d** | 값 수정 | 시계 설정 모드에서 시간 값 증가/감소 |

##### UART Key Input (PC -> FPGA)
*   **'u' / 'd'**: 시계 값 증가 / 감소
*   **'l' / 'r'**: 자리 선택 또는 스톱워치 제어 (Clear/Run-Stop)
*   **'s'**: 현재 FND 출력값(시간 또는 센서 데이터)을 PC 터미널로 전송

#### 🧩 모듈 상세 설명

##### 1. UART & FIFO
*   **UART RX/TX**: 비동기 통신을 수행하며, 1비트의 보드 레이트 오차를 줄이기 위해 **x16 오버샘플링** 기법을 적용했습니다.
*   **FIFO Buffer**: UART 수신 시 CPU가 즉시 처리하지 못해 데이터가 유실되는 것을 방지하기 위해 RX 단에 버퍼를 두었으며, TX 단에도 안정적인 데이터 송신을 위해 적용했습니다.
*   **ASCII Decoder/Sender**: UART로 입력된 'u', 'd', 'r', 'l' 등의 문자를 시스템 제어용 **Tick 신호**로 변환하거나, 시스템 내부의 숫자를 문자로 변환하여 전송합니다.

##### 2. Stopwatch & Watch (구조 위주)
*   **Stopwatch**: `stopwatch_control_unit`(FSM)에서 `RUN`, `STOP`, `CLEAR` 상태를 제어하며, `stopwatch_datapath`에서 100Hz 틱을 기준으로 밀리초부터 시간까지 카운트합니다.
*   **Watch**: 
    *   **Control Unit**: 일반 동작 모드와 시간 수정 모드를 관리합니다.
    *   **Modify Selector**: 버튼 입력을 받아 시/분/초/밀리초 중 수정할 위치를 결정합니다.
    *   **Datapath**: 현재 시간을 유지하며, 수정 신호 발생 시 해당 자리의 값을 가감합니다.

##### 3. Sensors
*   **SR04 (초음파 거리 센서)**: 40kHz 펄스를 발생시킨 후 Echo 신호의 High 유지 시간을 측정하여 거리(cm)로 환산합니다.
*   **DHT11 (온습도 센서)**: 단일 와이어 **Half Duplex** 통신을 통해 40비트 데이터를 수신하며, 체크섬(Checksum)을 통해 데이터의 유효성을 검증합니다.

#### 📊 시뮬레이션 및 전체 검증
시스템의 신뢰성을 확보하기 위해 개별 모듈 검증 후 통합 시뮬레이션을 진행했습니다.

| 검증 시나리오 | 확인 내용 |
| ------ | ------ |
| **Stopwatch 동작** | 정방향/역방향 카운트 및 Stop 상태에서만 Clear 동작 활성화 확인 |
| **Watch 수정 동작** | 시/분/초 각 단위별 자리 선택 및 값 증감(Up/Down) 정상 반영 확인 |
| **UART 명령 연동** | PC에서 'u' 입력 시 시계 값이 증가하고 's' 입력 시 데이터가 송신됨을 확인 |
| **센서 데이터 처리** | 초음파 거리(3cm, 103cm) 및 온습도 40비트 데이터 수신 및 FND 출력 확인 |
| **디바운싱 검증** | 버튼 입력 시 1클럭의 깨끗한 펄스 신호(Tick)만 생성되는지 확인 |

#### 🐛 Trouble Shooting
##### 1. ASCII Decoder Tick 생성 오류
*   **문제**: UART 명령 입력 시 한 번만 동작해야 할 Up/Down 기능이 매 클럭 반복됨.
*   **해결**: `rx_done` 신호(수신 완료 시점)를 활용하여 해당 시점에만 1클럭 펄스를 생성하도록 로직을 수정했습니다.

##### 2. 시계 모니터링 시 sw_2 누락 (UVM-style Testbench)
*   **문제**: 시계 검증 중 `hour` 값이 변해야 함에도 `sec` 값이 변하는 오류 발생.
*   **원인**: 검증용 Monitor 모듈에서 인터페이스의 `sw_2` 신호를 받아오지 않아 발생한 문제.
*   **해결**: 인터페이스 연결을 수정하여 `sw_2` 값을 정상 샘플링한 후 All Pass 확인.

##### 3. 초음파 센서 거리 계산 오차
*   **문제**: 계산된 거리값이 실제 거리보다 작게 나옴.
*   **해결**: 카운트를 0이 아닌 1부터 시작하게 하여 시간 측정 오차를 보정하고, 데이터시트 수식을 재검토하여 58us=1cm 공식을 정확히 적용했습니다.
